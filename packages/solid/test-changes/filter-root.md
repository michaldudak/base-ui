# Test changes: filter-root

All entries are in `menu/filter-root/MenuFilterRoot.test.tsx`.

- File-wide: the `renderNonStrict` renderer (`createRenderer({ strict: false })`) and `renderToString` are gone, since the Solid renderer has neither option nor SSR helper; "renders the trigger as often as a plain menu on mount" uses `render`. The `vi.mock('@base-ui/utils/platform')` became `vi.mock('#utils/platform')`. A local `Fragment` component (`(props) => props.children`) stands in for `React.Fragment` where a test picks the wrapper component at runtime.
- File-wide: every `fireEvent.change(input, { target: { value } })` on a `Menu.Input` became `fireEvent.input(...)`. React's `onChange` on a text input is the native `input` event, which is what the Solid input listens to (guide section 6). Affected: "keeps component-rendered item text after the item is filtered out", "hover-opened submenu ownership > closes and resets after a query was typed into the hover-opened submenu", the `openAndType` helper of "closing with a query", "IME composition > filters on the committed text, not the composition in progress", "leaving the menu > closes on Escape even with a query typed" (its comment was updated to name `fireEvent.input`).
- "filtering > prop: autoHighlight > updates the active descendant when filtering replaces a custom-id item", "filtering > uses the id from a custom trigger render element for popup labelling", "filtering > uses an explicit label from the popup render element", "accessible names > keeps a list label supplied through a render element", "accessible names > omits aria-controls when the list renders with an explicitly empty id", "accessible names > omits the list label when the trigger renders with an explicitly empty id": the element form `render={<div id="x" />}` became `render={(props) => <div {...props} id="x" />}`, with the attribute after the spread. In React the render element's own props win over Base UI's when merged, so the attribute has to come last to keep the same precedence. The Solid `resolveRenderedId`/`resolvePopupLabel` only read the part's own props, so these tests are likely to fail until the sources read the rendered element's id/label (or the tests are moved to the `id`/`aria-label` prop).
- "filtering > prop: autoHighlight > always highlights the first item when mounted inside an opened dialog": `it.skip`, needs Dialog and ScrollArea. Body kept as a block comment, translated to Solid syntax (`createSignal`, `open()`).
- "filtering" helpers `FilterableSubmenu` and `ParentNavigationMenu`: `FilterableSubmenu` no longer destructures `portalled`; `SubmenuPortal` is `dynamic(() => ((props.portalled ?? true) ? Menu.Portal : Fragment))`. In `ParentNavigationMenu`, `submenu` became a function `() => <Menu.FilterProvider>...` called in JSX (`submenu()`), because a JSX value created at the top of the component body would be created outside `Menu.Root` and never see its context.
- "filtering > supports a detached trigger in a filterable menu" and "handle > ...": `useRefWithInit(() => new Menu.Handle()).current` / `useRefWithInit(() => Menu.createHandle()).current` became a plain `const handle = ...`, since the component body runs once.
- "closing with a query > keeps the query until a popup that prevented unmounting is unmounted" and "closing with a query > resets the query when the menu is removed as its exit transition completes": the inline `rootProps={{ ... }}` objects are created once in a `const rootProps` (guide section 7: an inline JSX expression is a getter re-evaluated on every read). `React.createRef<Menu.Root.Actions>()` became `{ current: null }`. In `RemovedOnCloseMenu`, `if (!rendered) return null` became `<Show when={rendered()}>`.
- "keyboard navigation > does not rerender unaffected items when the highlight moves": React render counts rewritten to the Solid equivalent, as in `MenuItem.test.tsx` (menu-items.md). After ArrowDown the test waits for Rename to get `data-highlighted` and expects neither render function to have been called again (React expected the first one to re-render and the second not). Solid runs a render function once and updates the element in place.
- "keeps the query when the popup-close reset is canceled": the `if (reactMajor <= 18) ignoreActWarnings()` guard was removed; it only existed for React 18 act warnings.
- "never mounts the Empty children while items match": `React.useEffect(onEmptyMount, [])` became `useEffect(() => [], () => { onEmptyMount(); })` from `#utils/useEffect`.
- "server-side rendering > shows the empty state after hydration when no items are rendered": `it.skip`, needs `renderToString`/`hydrate` in the Solid test renderer. Body kept as a block comment.
- "accessible names > points aria-controls at the id of a server-created render element": `it.skip` (was `it.skipIf(reactMajor < 19)`). React-only: it passes a `react.lazy` Server Component element to `render`, which has no element form in Solid. Body kept as a block comment.
- "with a Viewport > keeps real focus on the input while the cursor moves through the list": unchanged, but `Menu.Viewport` is not exported by the Solid Menu yet, so it does not type-check or run until it is.

## Later fixes

- `MenuFilterRoot.test.tsx`, "does not repeat matching when navigating past hidden component labels": React passes the content as `{() => (<>...</>)}`. In the Solid port a payload render function must declare its parameter (the rule Solid's own `<Show>` uses), because a lone component child can itself arrive as a zero-argument accessor. The payload is unused, so the content is passed directly.
- `MenuFilterRoot.webkit.test.tsx`, `Test` helper: the input also gets a `ref` that focuses it when `autoFocus` is set. React DOM focuses `autoFocus` elements on mount; Solid does not.
